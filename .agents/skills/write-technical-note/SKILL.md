# Write Technical Note

1. 質問の論点を1つの短いタイトルに整理する。
2. 変化しうる情報や不確かな技術事項は調査する。公式文書、標準仕様、原論文を優先する。
3. `notes/<yyyy-mm-dd>-<short-slug>/index.html` を作る。既存ノートの構造と `styles/site.css` を再利用する。
4. 次の順序を基本に、質問に合う構成へ調整する。
   - 30秒でわかる答え
   - 全体像または処理フロー
   - 仕組みの詳細
   - 具体例
   - 注意点・適用しない場面
   - 参照元
5. 図解は HTML/CSS、表、コード、またはインライン SVG で作る。装飾目的だけの図は不要。
6. 読者が結論と根拠を区別できるように書く。不確かな点、前提、調査日を明示する。
7. 参照元にはページ名、提供元、URL、確認日を記載する。
8. ルートの `index.html` の共通知識インデックスに新しい解説ノートカードを先頭追加する。`data-title`、`data-category`、`data-kind="note"`、`data-keywords` を設定する。
9. 相対リンクと表示を検証する。

秘密情報、個人情報、ローカル環境固有の値は含めない。push、公開、デプロイは行わない。コミットは明示的に依頼された場合だけ行う。
