Morphos / Morphousを迷わず使う

自然界のモチーフから作られた配色・デザインシステム集について、まず何ができるものなのかを整理し、その後にAI指示・Web実装・資料作成での使い方をまとめる。

30秒でわかる答え

これは、自然モチーフをもとにした配色セットを選び、AIへの指示、Webテーマ、PowerPoint、Wordへ使える形で取り出せるサイトです。つまり「配色を考える作業」を減らし、UIや資料の中身を考える時間を増やすための道具です。

名前について

Qiita記事では主にMorphosと書かれています。一方、公開サイトのタイトルやGitHub READMEではMorphous表記も使われています。このノートでは、迷わないようにMorphos / Morphousと併記します。

まず何ができるものなのか

Morphos / Morphousは、動物、植物、鉱物、天候、風景などの自然モチーフから作られた配色・デザインシステムのカタログです。単なる色見本ではなく、選んだモチーフを複数の実用フォーマットに変換して使えます。

どのように使うのか

基本の流れ

  1. サイトを開く。
  2. 動物、植物、鉱物などから気になるモチーフを選ぶ。
  3. 目的に合わせて、AI用、CSS、PowerPoint、Wordの形式を選ぶ。
  4. コピーまたはダウンロードする。
  5. AI、Webプロジェクト、資料、文書へ貼り付ける。
  6. 最後に可読性、コントラスト、ブランドとの相性を確認する。

選び方

最初は色名や流行で選ぶより、成果物の用途から逆算します。

AIにUIを作らせるとき

最も分かりやすい使い方は、AIへの色指定です。色名ではなく、色の役割とカラーコードを渡せるため、AIの出力が安定しやすくなります。

手順

  1. サイトで雰囲気に合うモチーフを選ぶ。
  2. AI用カラーパレット、または色役割とカラーコードをコピーする。
  3. 作りたいUIの目的、対象ユーザー、制約を一緒に渡す。
  4. 「この配色を使う。ただし可読性とコントラストを優先」と明記する。
  5. 生成結果を見て、Primary、Accent、Background、Inkの使い方を調整する。

WebサイトやReactに組み込むとき

Web実装では、選んだ配色をCSS変数やshadcn向けトークンとして取り込みます。これにより、画面ごとに色を手作業で決めるのではなく、テーマとしてまとめて扱えます。

手順

  1. 使いたいシステムのtheme.cssまたはCSS変数を取得する。
  2. プロジェクトのグローバルCSSへ追加する。
  3. 既存の色トークンと衝突しないか確認する。
  4. Button、Card、Form、Alertなど主要コンポーネントに適用する。
  5. light/darkの両方で可読性を確認する。
/* 例: 取得したCSS変数をテーマとして読み込む */
@import "./themes/morphos-theme.css";

.primary-button {
  background: var(--primary);
  color: var(--primary-foreground);
}

shadcn/uiで見るポイント

  • backgroundとforegroundのコントラスト。
  • primaryを多用しすぎて画面がうるさくならないか。
  • muted、border、cardが自然に見えるか。
  • dark modeでAccentやSignalが沈みすぎないか。
  • 既存ブランドカラーがある場合、置き換えではなく補助テーマとして使うか。

PowerPointで使うとき

資料作成では、配色テンプレートをベースにすることで、表紙や見出しの色決めを短縮できます。

  1. 目的に近いモチーフを選ぶ。提案資料なら落ち着いたものを選ぶ。
  2. PowerPointテンプレートをダウンロードする。
  3. 表紙、見出し、強調、図解、注意書きの色を確認する。
  4. 会社指定テンプレートがある場合は、色だけ転用できるか確認する。
  5. 印刷・プロジェクター表示で読めるか確認する。

資料では、配色の統一よりも読みやすさが優先です。自然モチーフの色を全部使おうとせず、背景、本文、強調の3系統から始めると崩れにくくなります。

Word・仕様書で使うとき

文書では、派手さよりも長文の読みやすさが重要です。Morphos / Morphousは、仕様書やレポートのトーンを自然モチーフから整える用途に使えます。

  1. 長文で疲れにくいトーンのモチーフを選ぶ。
  2. Wordテンプレートをダウンロードする。
  3. 表紙、見出し、罫線、注記、表の色だけに限定して使う。
  4. 本文色は原則として濃いInk系にする。
  5. PDF化して見え方を確認する。

仕様書では、Accentを本文色に使うと読みにくくなります。強調したい見出しや図表の補助色に限定します。

迷ったときの判断表

迷い判断
どのモチーフを選ぶべき？成果物の印象より先に、本文の可読性とPrimaryの見やすさで選ぶ
AIに何を貼ればよい？モチーフ名、色役割、カラーコード、用途、制約をまとめて渡す
CSSをそのまま入れてよい？小規模なら試してよい。既存プロダクトではトークン名の衝突を確認する
全色を使うべき？使わない。背景、本文、Primary、Accentから始める
ブランドカラーと混ぜてよい？混ぜてよいが、Primaryをどちらにするか決める
資料に使って浮かない？背景と本文は控えめにし、自然モチーフ色は見出し・図表・強調に使う

注意点

  • 自然由来の配色でも、UIとして常に読みやすいとは限らない。
  • コントラスト、hover、focus、disabled、errorなど状態ごとの確認が必要。
  • 色だけで意味を伝えない。アイコン、テキスト、形状も併用する。
  • 既存ブランドがあるプロダクトでは、全面置き換えより一部適用から始める。
  • PowerPoint・Wordテンプレートはサイト側で開発中の要素もあるため、最終成果物は必ず目視確認する。
  • 公開GitHubのライセンスや利用条件を確認してから商用・再配布に使う。

実務上の結論

Morphos / Morphousは、デザイナーの代替ではなく、色決めの初速を上げる道具です。最初の配色案を自然モチーフから借り、AIやCSSに渡せる形式へ変換し、最後は可読性・アクセシビリティ・ブランド適合で人間が判断します。
