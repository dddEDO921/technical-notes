最近のGitコマンド: switch / restoreで何が変わったのか

git checkoutは「ブランチを切り替える」と「ファイルを戻す」の両方を担当していました。最近のGitでは、その曖昧さを避けるためにswitchとrestoreを使い分けると読みやすくなります。

30秒でわかる答え

ブランチを移動するならgit switch、ファイルの変更を戻すならgit restore、履歴やステージの位置を動かすならgit resetと考えると整理できます。checkoutは今も使えますが、役割が広く、操作意図が読み取りにくい場面があります。

なぜcheckoutから分かれたのか

git checkoutは歴史的に、ブランチ切り替えとファイル復元の両方を持つコマンドです。公式ドキュメントでも、checkoutには「branchを切り替える」モードと「別バージョンのファイルを復元する」モードがあると説明されています。

この2つは日常操作としてはまったく違います。そこで、Git 2.23でswitchとrestoreが追加され、操作の意図をコマンド名で分けられるようになりました。

よく使う操作の対応表

やりたいこと最近の書き方checkout時代の書き方
既存ブランチへ移動するgit switch feature/foogit checkout feature/foo
直前のブランチへ戻るgit switch -git checkout -
新しいブランチを作って移動するgit switch -c feature/foogit checkout -b feature/foo
特定commitを一時的に見るgit switch --detach <commit>git checkout <commit>
未ステージの変更を捨てるgit restore path/to/filegit checkout -- path/to/file
ステージから外すgit restore --staged path/to/filegit reset path/to/file
特定commitの内容でファイルを戻すgit restore --source=<commit> path/to/filegit checkout <commit> -- path/to/file

switchはブランチ操作

git switchは、指定したブランチへ移動するためのコマンドです。作業ツリーとindexは、移動先ブランチに合わせて更新されます。ただし、ローカル変更が失われる可能性がある場合は、通常は操作が中断されます。

# 既存ブランチへ移動
git switch main

# 新しいブランチを作って移動
git switch -c feature/login

# 直前のブランチへ戻る
git switch -

# commitを一時的に見る detached HEAD
git switch --detach HEAD~3

新規ブランチ作成では-cを使います。既存ブランチを同名で作り直す-Cもありますが、既存branchの位置を動かすため、普段使いでは慎重に扱います。

restoreはファイルを戻す操作

git restoreは、指定したパスを復元するためのコマンドです。何を復元元にするか、どこを復元先にするかで意味が変わります。

コマンド復元先意味
git restore fileWorking tree未ステージの変更をindexの内容へ戻す。手元の編集を捨てる。
git restore --staged fileIndexステージ済みの内容をHEADへ戻す。作業ツリーの変更は残る。
git restore --staged --worktree fileIndex + Working treeステージと作業ツリーの両方を戻す。
git restore --source=HEAD~1 fileWorking tree指定commitの内容で作業ツリーのファイルを戻す。
git restore -p file選択したhunk差分の一部だけを対話的に戻す。
restoreの注意

git restore fileは、未ステージの手元変更を捨てます。戻したいだけなのか、退避したいのかが曖昧なときは、先にgit diffやgit statusで確認します。

resetとの違い

git resetは、HEADやindexを既知の状態に戻すコマンドです。ファイル単位でステージから外す目的にも使われてきましたが、現在は「ステージから外す」だけならgit restore --stagedの方が意図を読み取りやすいです。

目的おすすめ補足
ステージから外すgit restore --staged file作業ツリーの変更は残る。
直前commitをやり直すgit reset --soft HEAD~1HEADだけ戻し、indexと作業ツリーは残す。
commitもステージも戻すgit reset --mixed HEAD~1--mixedはresetの既定。
すべて捨てて戻すgit reset --hard <commit>作業ツリーも上書きするため危険。

実務での使い分け

  • ブランチを移動するならgit switchを使う。
  • ブランチを作って移動するならgit switch -cを使う。
  • ファイルの未ステージ変更を捨てるならgit restoreを使う。
  • ステージから外すだけならgit restore --stagedを使う。
  • 履歴の位置を動かすならgit resetを使う。
  • 古い記事や既存スクリプトのcheckoutは無理に置き換えなくてよいが、新しく書く手順書ではswitch / restoreを優先する。

覚え方

switch
ブランチを選ぶ
restore
ファイルを戻す
reset
状態の基準を戻す

checkoutは「昔からある万能寄りの道具」です。悪いコマンドではありませんが、チームの手順書やレビューコメントでは、目的が伝わるswitchとrestoreを使う方が読み手に親切です。
