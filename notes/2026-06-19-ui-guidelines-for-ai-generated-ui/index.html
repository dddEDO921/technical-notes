AI生成UIに効くUIガイドライン

AI生成UIの品質を上げるために、まず代表的なUIガイドラインを知り、次にAIへどう渡すかを整理する。参考記事の「Qt風が効く」という話は最後に補足として扱う。

30秒でわかる答え

「Qt風」が効く理由は、派手な装飾ではなく、成熟したデスクトップアプリらしい制約がAIに入るからです。標準部品、控えめな色、明確な余白、整列、状態表現、密度のある情報配置を指定すると、AIが作りがちな大きすぎるカード、過剰なグラデーション、曖昧な階層を避けやすくなります。

1. まず、こんなUIガイドラインがある

AIに「いい感じに」「モダンに」と頼むより、既存のUIガイドライン名を指定した方が出力が安定しやすくなります。ガイドライン名は、見た目の雰囲気だけでなく、部品、余白、状態、操作感、情報密度のまとまった制約として働きます。

3. AIにはこんなふうに渡すとよい

ガイドライン名だけでも効くことはありますが、実務では「どのガイドラインに従うか」と「どの要素を守るか」をセットで渡す方が安定します。

基本テンプレート

以下のUIを作ってください。

デザイン方針:
- [Qt風 / Material Design / Apple HIG / Fluent 2] を参考にする
- ただし、ブランド模倣ではなく、レイアウト・余白・部品・状態表現の原則を使う

守ること:
- 画面の主目的を1つにする
- Primary / Secondary / Destructive を明確に分ける
- hover / focus / disabled / loading / error の状態を用意する
- 余白、整列、境界線で情報階層を作る
- 色だけで状態を伝えない
- キーボード操作とアクセシビリティを考慮する

避けること:
- 巨大カードの乱用
- 過剰な角丸
- 派手なグラデーション
- 装飾目的の強い影
- 余白が広すぎるランディングページ風の見た目

Qt風に寄せたい場合

このUIを、Qt風の成熟したデスクトップアプリの見た目で作ってください。

重要:
- ランディングページ風にしない
- ツールバー、パネル、表、フォーム、ステータスバーを使う
- 背景はニュートラル、境界線と余白で階層を作る
- Primaryボタンは1画面に1つ程度
- 8px単位の余白で整列する
- 業務アプリとして長時間使っても疲れない情報密度にする
- hover / focus / disabled / selected / loading / error状態を定義する

Material Designに寄せたい場合

Material Designを参考にしてください。

ただし:
- カードを増やしすぎない
- elevationは情報階層を示す目的に限定する
- タップ領域、状態変化、入力エラーを明確にする
- Primary色は主要アクションに限定する

Fluentに寄せたい場合

Fluent 2 Design Systemを参考にした業務アプリUIにしてください。

重視すること:
- コマンドバー、ナビゲーション、表、詳細ペインを自然に配置する
- Microsoft 365系の業務ツールのような落ち着いた密度にする
- アクセシビリティ、focus order、状態表現を明確にする

4. なぜAI生成UIは安っぽく見えやすいのか

よくある出力安っぽく見える理由直す方向
巨大な角丸カードを多用する情報密度が低く、部品の役割が曖昧になるカードを必要な単位に限定し、表・ツールバー・リストを使う
派手なグラデーションと影装飾が情報より目立つ背景は控えめにし、強調色は操作や状態に限定する
余白が大きすぎる業務ツールとしての密度が足りない8px単位などの余白ルールを決め、コンパクトにする
ボタンの優先順位が全部同じ次に何をすべきか分からないPrimary / Secondary / Destructiveを明確に分ける
フォームや表の整列が甘いプロっぽさが失われるラベル、入力欄、数値、アクションを揃える
状態表現が弱い操作可能、読み込み中、無効、エラーが区別できないhover、focus、disabled、loading、errorを明示する

5. Qt風デザインが効く理由

QtはクロスプラットフォームのGUIフレームワークで、デスクトップアプリケーションの文脈が強いです。AIに「Qt風」と指定すると、次のような方向へ寄りやすくなります。

  • WebのLPではなく、実用アプリの画面として構成する。
  • ツールバー、メニュー、パネル、表、フォームなど標準的な部品を使う。
  • 色や影を控えめにし、操作対象と情報を優先する。
  • 余白、境界線、区切り、整列で階層を作る。
  • 情報密度を上げても破綻しないレイアウトにする。
  • 派手さよりも、安定感、実用性、OSネイティブ感を優先する。
実務での解釈

「Qt風」は、見た目のブランド名というより「業務アプリらしい制約」をAIへ入れるためのショートカットです。

6. UIガイドラインとしてAIに渡す具体項目

ガイドライン名だけで足りない場合は、以下の観点を明示します。

観点指示する内容避けるもの
レイアウトヘッダー、サイドバー、ツールバー、メイン領域、詳細ペインを明確に分ける全部をカードの羅列にする
余白8px単位で余白を揃え、関連要素は近づける意味なく広い余白
色中立色をベースにし、Accentは主要操作や状態だけに使う全面グラデーション、過剰な彩度
タイポグラフィ見出し、ラベル、本文、補足のサイズ差を控えめにする巨大見出し、太字の乱用
コンポーネントOS/デスクトップアプリ風の標準部品を使う独自すぎるボタンや入力欄
状態hover、focus、active、disabled、loading、errorを定義する通常状態だけ作る

アクセシビリティキーボード操作、focus ring、コントラスト、ラベルを確保する色だけで意味を伝える

7. Qt風に寄せる具体ルール

1. レイアウトはアプリケーション構造にする

画面は以下の構造にしてください。
- 上部: タイトルバーまたはツールバー
- 左: ナビゲーションまたはフィルタペイン
- 中央: 表、一覧、フォームなど主要作業領域
- 右: 選択項目の詳細ペイン
- 下部: ステータスバーまたは補足情報

2. 色は控えめにする

色はQt風のデスクトップアプリとして控えめにしてください。
- 背景は薄いニュートラル
- 境界線で区切る
- Primary色は主要アクションだけに使う
- 危険操作は赤系で明確にする
- 装飾目的のグラデーションは使わない

3. 部品の役割を明確にする

以下のコンポーネントを標準的なデスクトップアプリ風にしてください。
- Toolbar
- Menu button
- Table
- Tree view
- Form field
- Dialog
- Tabs
- Status bar

各部品に hover / focus / disabled / selected の状態を用意してください。

4. 密度を上げる

業務ツールとして使える情報密度にしてください。
カードを多用せず、表・リスト・ペインを使ってください。
余白は8px単位で揃え、要素間の関係が分かるようにしてください。

8. AI生成UIレビューのチェックリスト

  • 画面の主目的が1つに見えるか。
  • PrimaryアクションとSecondaryアクションが区別できるか。
  • カードや影が情報構造ではなく装飾として増えていないか。
  • 表、リスト、フォームのラベルと値が揃っているか。
  • hover、focus、disabled、loading、error状態があるか。
  • 色だけで状態を表していないか。
  • 情報密度が用途に合っているか。
  • 長時間使う業務ツールとして疲れないか。
  • キーボード操作とfocus順が破綻していないか。
  • OSネイティブ風にするなら、独自部品を増やしすぎていないか。

9. 参考記事の内容

参考記事では、AIにフロントエンドを生成させると「指定したスタイル + 安っぽさ」になりがちだが、「Qtアプリのように見せて」と指定すると、その安っぽさが大きく減ったという観察が紹介されています。

この話は興味深いですが、主観的な実験です。実務で使うなら「Qt風」という言葉だけに頼らず、Qtのような成熟したUIガイドラインが持つ具体的な制約をプロンプトや実装ルールに落とすのが重要です。

10. 記事から得るべきポイント

元記事の価値は「Qtと書けば万能」という話ではありません。AIは曖昧なデザイン指示を受けると、学習データ上の平均的で派手なWeb UIへ寄りがちです。そこで、Qt Quick Controls GuidelinesやMaterial、Apple HIG、Fluentのような確立済みUIガイドライン名を使うと、AIにまとまった制約セットを渡せます。

実務上の結論

AI生成UIを安っぽくしないコツは、「かっこよく」ではなく「どのガイドラインに従うか」と「どの部品・余白・状態・密度にするか」を具体的に指示することです。Qt風は、特に業務ツールや個人用管理画面で効きやすい指定です。
