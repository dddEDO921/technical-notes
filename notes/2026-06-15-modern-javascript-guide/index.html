モダンなJavaScript実装ガイド

新しい構文を並べるだけではなく、標準APIを優先し、依存関係・非同期処理・副作用を制御して、安全で検証可能なコードを書くための実務指針。

30秒でわかる答え

モダンなJavaScript実装とは、ES Modulesで責務を分け、標準APIを活用し、非同期処理をキャンセル可能にし、DOM操作と外部入力を安全に扱うことです。さらに、必要なJavaScriptだけを配信し、テスト・Lint・型チェックで変更の安全性を保ちます。

「モダン」の判断基準

新しい構文を使っているかより、次の性質を満たすかで判断します。

標準を優先し
依存を減らす
責務と副作用を分け
テスト可能にする
性能・安全性・互換性を
計測して判断する
  • 対象ブラウザ・ランタイムを明確にし、対応状況を確認して機能を選ぶ。
  • ブラウザやJavaScript標準で解決できることに、不要なライブラリを追加しない。
  • 状態変更、ネットワーク、DOM操作などの副作用を境界へ寄せる。
  • 失敗、キャンセル、タイムアウト、再試行を正常系と同じように設計する。
  • 初期表示に不要なJavaScriptを送らず、実行時間を含めて性能を考える。

1. ES Modulesで責務を分ける

ブラウザはES Modulesを標準で扱えます。import・exportで依存関係を明示し、グローバル変数や実行順への暗黙依存を避けます。

// api/users.js
export async function getUser(id, { signal } = {}) {
  const response = await fetch(`/api/users/${encodeURIComponent(id)}`, { signal });

  if (!response.ok) {
    throw new Error(`User request failed: ${response.status}`);
  }

  return response.json();
}

// pages/profile.js
import { getUser } from "../api/users.js";

モジュールは「小さければよい」のではなく、変更理由と責務がまとまっていることが重要です。公開APIを絞り、内部実装を隠すことで変更範囲を限定できます。

Dynamic Importを使う場面

button.addEventListener("click", async () => {
  const { openEditor } = await import("./editor.js");
  openEditor();
});

重い機能を必要になった時点で読み込めます。ただし細かく分割しすぎると通信・管理コストが増えるため、利用頻度とバンドル分析を基準に判断します。

2. データを明示的に扱う

constを基本にし、再代入が必要な場合だけletを使います。値の変化を追いやすくし、意図しない共有状態を減らします。

function calculateTotal(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}

const total = calculateTotal(cartItems);

純粋関数は同じ入力に対して同じ出力を返し、外部状態を変更しません。ビジネスロジックを純粋関数へ寄せると、DOMやネットワークなしでテストできます。

Optional ChainingとNullish Coalescing

const displayName = user.profile?.displayName ?? "名称未設定";

?.はnull・undefinedを安全に扱い、??はその2値だけを欠損として既定値を返します。||と違い、0や空文字を有効値として保持できます。ただし、必須データまで黙って欠損扱いにすると不具合を隠すため、契約違反は明示的に失敗させます。

深いコピー

const editableDraft = structuredClone(originalData);

対応するデータ型の深いコピーにはstructuredClone()を使えます。JSONへの変換をコピー目的で使うと、Date、循環参照、undefinedなどを正しく扱えません。

3. 非同期処理を設計する

async/awaitはPromiseを読みやすく扱う構文です。重要なのは、直列・並列・部分失敗のどれが要件に合うかを明示することです。

独立した処理は並列化する

const [user, notifications] = await Promise.all([
  fetchUser(),
  fetchNotifications(),
]);

前の結果を必要としない処理を順番にawaitすると、待ち時間を不要に足し合わせます。一方、1件の失敗で全体を失敗させたくない場合はPromise.allSettled()を検討します。

キャンセル可能にする

let activeController;

async function searchUsers(query) {
  activeController?.abort();
  activeController = new AbortController();

  try {
    const response = await fetch(`/api/users?q=${encodeURIComponent(query)}`, {
      signal: activeController.signal,
    });

    if (!response.ok) throw new Error(`Search failed: ${response.status}`);
    return await response.json();
  } catch (error) {
    if (error.name === "AbortError") return [];
    throw error;
  }
}

検索入力、画面遷移、コンポーネント破棄などでは、不要になったリクエストをAbortControllerで中止します。古いレスポンスが新しい画面を上書きする競合も防ぎやすくなります。

Fetchの注意点

fetch()はHTTP 404や500だけではrejectしません。ネットワークエラーとHTTPエラーを区別し、response.okまたはステータスを確認します。再試行は冪等性、回数、待機時間、サーバー負荷を考慮して設計します。

4. DOM操作を安全で局所的にする

DOM操作は副作用です。データ変換と表示更新を分離し、DOM探索やイベント登録を特定のモジュールへ閉じ込めます。

function createUserItem(user) {
  const item = document.createElement("li");
  const name = document.createElement("strong");

  name.textContent = user.name;
  item.append(name);
  return item;
}

外部入力を表示するだけならtextContentを使います。信頼できない文字列をinnerHTMLへ直接入れるとDOM-based XSSにつながります。HTMLを受け入れる必要がある場合は、要件を限定し、実績あるサニタイザー、Content Security Policy、Trusted Typesなどを組み合わせます。

イベント委譲

list.addEventListener("click", (event) => {
  const button = event.target.closest("[data-delete-id]");
  if (!button || !list.contains(button)) return;

  deleteItem(button.dataset.deleteId);
});

動的な一覧では親要素へイベントを登録することで、各要素への大量登録を避けられます。対象要素と境界を必ず確認します。

5. 標準Web APIを優先する

モダンブラウザには、以前はライブラリが必要だった機能が標準で用意されています。

標準APIを選ぶ前に対象環境の対応状況を確認します。機能検出、段階的強化、フォールバックを使い、ユーザー環境に合わない最新機能を無理に採用しません。

6. 必要なJavaScriptだけを実行する

JavaScriptはダウンロード後に解析・コンパイル・実行され、メインスレッドを占有します。ファイルサイズだけでなく実行コストを減らします。

  • HTMLとCSSで実現できる機能をJavaScriptで再実装しない。
  • 初期表示に不要な機能はdynamic importで遅延読み込みする。
  • 大きな処理を分割し、入力応答を長時間ブロックしない。
  • CPU負荷の高い処理は必要に応じてWeb Workerへ移す。
  • 依存ライブラリのサイズ、重複、実際の利用箇所を定期的に確認する。
  • 推測ではなく、Performance panel、Lighthouse、実ユーザー計測などで確認する。

7. 型・Lint・テストで変更を守る

JavaScriptプロジェクトでも、JSDocとcheckJs、またはTypeScriptを使うと、API境界やデータ構造の不整合を早期に検出できます。型は実行時検証の代わりではないため、外部入力は別途検証します。

/**
 * @param {{ price: number, quantity: number }[]} items
 * @returns {number}
 */
export function calculateTotal(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}

8. 状態とアーキテクチャを単純に保つ

状態管理ライブラリを導入する前に、状態の所有者、寿命、更新経路を決めます。状態は利用範囲に最も近い場所へ置き、同じ情報を複数箇所で持たないようにします。

実装レビューのチェックリスト

  • 対象ブラウザ・Node.jsバージョンに対応しているか。
  • 標準APIで十分な処理に新しい依存を追加していないか。
  • モジュールの責務と公開APIが明確か。
  • 非同期処理の失敗、キャンセル、競合を扱っているか。
  • 外部入力を検証し、安全なDOM APIを使っているか。
  • 初期表示に不要なJavaScriptを読み込んでいないか。
  • 重要なロジックをDOMや通信から分離し、テストできるか。
  • アクセシビリティを標準HTML・UI要素と実ブラウザで確認したか。
実務上の結論

モダンJavaScriptの目的は「新しい書き方を使うこと」ではなく、ブラウザ標準を活かしながら、変更しやすく、失敗に強く、利用者へ余計な負荷を与えない実装を作ることです。
